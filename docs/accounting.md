# 計量與計價說明

這份文件說明 Token Usage 如何從三個來源取得用量、如何去重與歸屬，以及費用怎麼算。

## 共通原則

- **只增不刪**：已記錄的用量不會因為原始檔案被刪除而消失。重新掃描只會新增或修正，不會移除。
- **修正留痕**：同一筆請求的計數被來源修正時，Codex 會更新原事件；Claude Code 與 Antigravity 會把舊值寫進修訂紀錄表，再更新帳目。
- **只存計數**：Claude Code 與 Antigravity 帳本只保存模型、時間、Token 分類、雜湊後的對話與來源識別，以及來源行號。Codex 統計另外保存 Codex 自己記錄的對話標題與專案路徑。三者都不保存回覆、思考內容或工具輸出。
- **不猜測**：缺少穩定身份、格式不符或計數互相矛盾的紀錄不匯入，並在頁面上提示。
- **時間區間**：自訂區間包含開始時刻、不包含結束時刻，以頁尾顯示的計量時區解釋。
- **Token 分類**：在網頁與匯出中，Cached Input 與 Cache Write 是 Input 的子集，Reasoning 是 Output 的子集，Total 不會重複加總。

## 中轉站模型名稱與計費方式

### 自動對應

中轉站常在模型名稱前後加上自己的路由文字，例如 `relay/claude-opus-5.5:thinking`、`pool/auto-claude-opus-5-5`。三個來源都用同一條規則把這類名稱對應到內建模型：

1. 只看最後一個 `/` 之後、第一個 `:` 之前的部分。
2. 從完整名稱開始，依序去掉開頭到下一個 `-`、`_` 或 `.` 為止的文字，取第一個（也就是最長的）認得的內建模型名稱。
3. 名稱只是「以內建模型開頭」的不對應，例如 `gpt-6.1-sol-mini` 可能是另一個模型；`codex-auto-review` 的零價規則不會被對應。

自動對應的模型按對應模型的價格計算：Claude Code 與 Antigravity 依每筆請求當天的日期費率，也套用快速模式、地區與長上下文規則；Codex 也套用 Fast 額度倍率。「定價設定」的「檢視自動對應價格」列出目前自動對應的模型、對應到的模型與今天適用的價格。

手動設定一律優先：按「移除自動對應」後，可以改成對應到其他內建模型、填寫自訂單價或保持未定價；保持未定價會存成一筆設定，所以不會再被自動對應回去。手動設定旁的「恢復自動對應」會刪除這個模型的手動設定。

### 計費篩選

篩選面板的「計費」可以只看訂閱或只看 API（中轉站、API 金鑰等按 Token 計費的服務）的用量：

- **Codex**：每次回應的用量紀錄附有額度資訊，其中的 `plan_type` 是服務這次請求的 ChatGPT 方案。回合內的回應有方案（例如 `plus`、`team`）算訂閱，沒有方案算 API；透過中轉站轉送、但回傳了方案的請求也算訂閱。沒有額度資訊的回合才改看對話記錄的 `model_provider` 與模型名稱：服務商不是 `openai`，或模型名稱像中轉站（含 `/`、`:`，或可以自動對應）算 API，其他算訂閱。`model_provider` 只在對話建立時記錄一次，之後換服務商不會更新，Codex 也會改寫它，所以只作為備用。原始檔已刪除的舊紀錄無法重讀，只能用備用規則。
- **Claude Code**：對話紀錄沒有記錄連線的伺服器，也沒有記錄登入方式，只能看模型名稱：名稱像中轉站的算 API，其他算訂閱。直接使用官方模型名稱的中轉站，或用官方 API 金鑰的請求，會被算成訂閱。
- **Antigravity**：一律算訂閱。

篩選只影響顯示哪些用量，不讀取、也不顯示中轉站的餘額或額度。

## Codex

### 來源

讀取 `CODEX_HOME` 下 `sessions/` 與 `archived_sessions/` 的 JSONL。Codex 狀態資料庫只用來找出檔案路徑並補充標題、專案等資訊，資料庫裡的 `tokens_used` 不計入總量。`tokens_used` 是對話目前的累計計數，不含壓縮對話的請求（Codex 以獨立的請求紀錄寫出，不併入累計），也不含復原或還原檢查點前已送出、之後被撤回的請求，所以本程式的對話合計可能比它高。

Codex 會把較舊的對話壓縮成同名的 `.jsonl.zst` 並刪除原檔。程式把壓縮檔當成原本那個 JSONL，從上次讀到的位置接著讀解壓後的內容，所以服務停止期間才寫入、隨後被壓縮的用量也會補記，已記錄的部分不會重複計算。同名的 `.jsonl` 仍在時以 `.jsonl` 為準。

### 去重與歸屬

- 新格式紀錄以 `token_usage_record` 為準，依對話與 `response_id` 去重，並用 `turn_token_usage` 核對已入帳的增量；一般回應與壓縮請求都會計入。
- 沒有獨立請求紀錄的舊格式以累計值差分計算；重送舊快照或從中途恢復時只計新增部分。
- 一個 JSONL 的所屬對話由第一筆 `session_meta` 決定。Fork 檔案中複製進來的父對話歷史只作為基準，不算成子對話的新用量。
- 同一個對話可能分散在多個 JSONL：繼續對話、復原上一步、還原檢查點時，Codex 都會用同一個對話 id 寫新檔案。累計值以整個對話為範圍時，程式會記下已計入的每個累計狀態（`session_points`），每筆快照依序判斷：
  - 同一個請求（累計值和 `last_token_usage` 都相同）已經計入過：是恢復時帶回的舊狀態，不再計入。
  - 請求的起點（累計值減 `last_token_usage`）是已計入的狀態：是從那一點送出的新請求（例如復原後重新送出），計入 `last_token_usage`，屬於確定的數字。
  - 接續同一檔案自己的上一筆快照：照常計算差值。
  - 都對不上時才用 `last_token_usage` 保守補位，標為補位並提示 `cumulative_gap_fallback`；之後讀到原本那筆時不會再計一次。
  - 檔案依檔名中的建立時間讀取，不論在 `sessions` 還是 `archived_sessions`，所以一個對話一定先於接續它的檔案讀到；重新掃描、服務重啟或重建的結果相同。每回合重新起算的計數仍以回合識別。
  - 開頭就帶著累計、前面沒有任何已計入狀態的檔案（例如 Codex 把較早回合壓縮掉的 subagent），整段累計都算這個對話的用量，因為那些用量不會出現在別處。
  - 升級前已讀過的檔案，第一次需要時會重讀一次同一對話的檔案，補記已計入的狀態。
- 用量歸到紀錄時間所在的計量日，不依對話最後更新時間歸日。
- 檔案被截斷或改寫時保留現有統計並提示；只有在網頁上確認，或執行 `token-usage scan --rebuild`，才會從現存 JSONL 重建。已刪除的 JSONL 在重建後無法恢復。只有修改時間變動、大小與內容不變的檔案（例如被備份或防毒軟體動過時間）會先核對開頭雜湊與最後的累計 Token，相符就繼續掃描，不會提示重建。

### 計量時區

計量時區以 IANA 名稱存在統計庫中，所有程序與瀏覽器使用同一個時區。第一次建立統計庫時採用 `TOKEN_USAGE_TIMEZONE`，沒設定則使用系統時區；之後更改系統時區不會影響已保存的值。

### 計價

- 使用內建的 OpenAI Standard 文字價格表（USD／每 100 萬 Token），Cached Input 與 Cache Write 從 Input 扣除後分別計價，Reasoning 已包含在 Output 中。
- 明確標記為 Fast 的用量，費用按 Codex 額度倍率折算：GPT-6.1 Sol、GPT-6 Astra／Sol／Luna、GPT-5.6 系列與 GPT-5.5 為 2.5 倍，GPT-6.2 Astra／Sol 與 GPT-5.4 為 2 倍。沒有已確認倍率的模型會標為未定價。Token 數本身不乘倍率。
- `codex-auto-review` 預設以零元計算，Token 照常統計；可以在「定價設定」覆寫。
- 可在「定價設定」把內部模型指定為某個內建模型的別名、填入自訂單價，或把會自動對應的模型保持未定價（`{ "unpriced": true }`）。內建模型不能覆寫；以前替尚未定價的模型填的自訂單價，在新版加入該模型的官方價格後會被略過，改用官方價格。設定存在 `config.json` 的 `pricing_overrides`：

```json
{
  "pricing_overrides": {
    "internal-review": { "alias_of": "gpt-6.1-sol" },
    "internal-model": {
      "input_usd_per_million": "1.00",
      "cached_input_usd_per_million": "0.10",
      "cache_write_input_usd_per_million": "1.25",
      "output_usd_per_million": "6.00"
    }
  }
}
```

## Claude Code

### 來源

遞迴讀取 `~/.claude/projects` 與 `~/.config/claude/projects` 下的 JSONL，包含子代理與已同步到本機的 SSH 會話。`CLAUDE_CONFIG_DIR` 可改為其他資料夾（逗號分隔）。檔案最後一行若尚未寫完，留到下次掃描。

### 去重與歸屬

- 每個請求以「message ID＋request ID」識別；沒有 request ID 時改用「對話＋message ID」。同一請求的多個內容區塊、跨檔複製只計一次；同一請求出現多個版本時取各分類都不小於前者的完整值。
- 子代理（sidechain）檔案中重播的父對話訊息不重複計算；已存在的這類舊紀錄會標記排除並保留稽核紀錄。
- `advisor_message` 迭代以自己的模型另外記一筆，一般迭代不重複加總。最上層的 Token 計數全為 0、實際用量只記在一般迭代（`message`）時，改用這些迭代的加總。
- 模型以當次選擇為準（有 `requestedModel` 時），版本寫法統一，例如 `claude-opus-5.5` 與 `claude-opus-5-5` 視為同一模型。

### Token 分類

- `output_tokens` 已包含思考 Token；有拆分資料時顯示為 Reasoning，計價只算一次。
- 快取寫入分成 5 分鐘與 1 小時兩種，分別計價；不把快取寫入當成一般輸入。

## Antigravity

### 來源

掃描 `~/.gemini/antigravity`、`antigravity-ide`、`antigravity-cli` 三個資料夾的 `brain/<對話>/.system_generated/logs/transcript.jsonl`，並唯讀開啟 `conversations/<對話>.db`。`ANTIGRAVITY_TRACKER_HOME` 可改為其他資料夾。

- 沒有 transcript 的對話（例如由其他代理執行的對話）只讀資料庫。
- Antigravity 會刪掉長對話 transcript 的開頭；transcript 裡已經沒有的步驟，改從資料庫補上。
- 已經從 transcript 記下的步驟，之後即使 transcript 不見了，也保留當時 transcript 所顯示的模型，不會被資料庫的結果取代。
- 同一個步驟編號可能用到不只一次：回到檢查點繼續後，Antigravity 會重用之後的步驟編號；CLI 在同一段對話的每個回合都從 0 編號。資料庫只保留每個編號最後一次的內容。每一次使用都算一個請求：最後一次以步驟編號識別，並取用資料庫的用量；較早的幾次以「步驟編號＋回應時間」識別，用 transcript 自己的計數。編號與時間都相同的回應視為同一個請求，只算一次。
- 對話的 transcript、資料庫與 `-wal` 檔的大小和修改時間都沒變時，掃描會略過該對話。

### 用量來源的優先順序

每一筆規劃回應（`PLANNER_RESPONSE`）依序取用：

1. **對話資料庫 `gen_metadata`**：原生用量統計，含輸入、快取讀取、快取寫入、總輸出、思考與回應輸出。
2. **對話資料庫 `steps` 中的用量**：`gen_metadata` 沒有該步驟時使用。
3. **transcript 內的計數欄位**：資料庫都沒有時使用。
4. **文字估算**：以上皆無時，以字元數估算（中日文每字 1 Token，其他每 4 字元 1 Token），並標為「估算」，與實際計數分開顯示。

已經存有實際計數的紀錄，不會被估算值或較粗略的 transcript 計數覆蓋。

### 模型歸屬

以當次的模型選擇為準：優先採用資料庫記錄的選擇標籤，其次是 transcript 中「Model Selection」設定變更的時間軸。兩者都沒有時，採用資料庫記錄的服務模型 ID；連 ID 也沒有，就沿用同一對話前一步的模型。名稱統一成小寫並去掉思考等級，例如「Gemini 3.1 Pro (High)」記為 `gemini-3.1-pro`；服務模型 ID 的 `-s`、`-trial` 後綴也會去掉，例如 `gemini-4-argon-s` 記為 `gemini-4-argon`。

「Orchestrator (Carbon)」、「Orchestrator (Argon)」與「Orchestrator (Neon)」不是單一模型：括號裡的模型負責規劃與審查，Gemini 4 Hydrogen 負責實作。每一步依資料庫記錄的模型身分歸屬，模型 ID 含 `orchestrator` 的步驟記為規劃模型（`gemini-4-carbon`、`gemini-4-argon` 或 `gemini-4-neon`），含 `worker` 的步驟記為 `gemini-4-hydrogen`，各自依該模型的費率計價。

## 「整體」如何合併

- Token、事件數、對話數直接相加；每日與每小時趨勢依日期與小時合併。
- 模型分組以統一後的模型名稱合併；來源分組會出現 Codex 的各來源，以及「Claude Code」、「Antigravity」。
- 費用由各來源依自己的規則先算好再相加，不會用 Codex 價格表去算 Claude Code 或 Antigravity 的用量。
- 對話列表依最後使用時間排序，三個來源混合顯示。

## 額度頁的 Token 合計

「額度」頁的已用百分比與重置時間直接採用各工具回報的數值，不由 Token 推算（來源見 README 的「額度」）。每一期旁邊的 Token 合計，是該工具從「重置時間往前推一個週期長度」起、到重置時間（尚未重置時為現在）為止的訂閱用量（經中轉站或 API 金鑰計費的請求不會用到訂閱額度，所以不計入；判斷方式見「中轉站模型名稱與計費方式」），依本文件同樣的去重規則計算，不依帳號拆分；同一段時間用過多個帳號時，合計會包含所有帳號。
